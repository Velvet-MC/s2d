## Summary

S2D (Schematic-to-Dragonfly) is a Go library that reads Java-edition Minecraft
schematic files (Sponge `.schem` and legacy MCEdit `.schematic`) and translates
them into Dragonfly `world.Block` values, ready to be placed into any
Dragonfly-based Bedrock server.

The library handles two concerns end-to-end:

1. **Schematic parsing.** Decode the file format (gzipped Java NBT) into an
   in-memory representation of cells, palette entries, and metadata.
2. **Java→Bedrock block-state translation.** Resolve each Java block-state
   string (e.g. `minecraft:oak_log[axis=y]`) to a Dragonfly `world.Block`
   value — including waterlogged variants which become a base block plus a
   liquid layer.

S2D is intentionally narrow: it does not register commands, store files, manage
clipboards, or write to a `world.Tx`. Consumers (a WorldEdit plugin, a world
converter, a structure-import tool, a proxy that needs to display Java
content on Bedrock, etc.) decide how to use the parsed result.

## Goals

- Parse a Sponge Schematic v2 (`.schem`) file into a `*Schematic` value with
  positions, blocks, and an unknown-block report — without the consumer
  needing to know the NBT layout.
- Parse a legacy MCEdit (`.schematic`) file into the same `*Schematic` shape.
- Translate every vanilla Java block-state to its Bedrock equivalent
  `world.Block`, including stateful blocks (logs, stairs, slabs, doors,
  fences, walls) and waterlogged variants (returned as block + liquid).
- Replace blocks with no Bedrock equivalent with a configurable visible
  marker (default `minecraft:wool[color=magenta]`) and report them back to
  the consumer in a structured `UnknownReport`.
- Ship as a single `go get` with all translation data embedded — no network
  access, no separate install step, no runtime config files required.
- Be reusable by any Dragonfly-based project. The public API surface is
  small and stable.

## Non-goals (v1.0)

- Writing schematic files (Bedrock → Java reverse translation).
- Block-entity translation (chest contents, sign text, banner patterns).
  Containers and signs come through as their base block only.
- Entities and biomes from `.schem` files.
- Sponge Schematic v3, Litematica `.litematic`, vanilla structure NBT
  (`.nbt`). Deferred to S2D v1.1.
- Modded blocks. Only vanilla translations are guaranteed; modded blocks
  fall through to the missing-block marker.
- Application-level concerns (commands, clipboards, file storage, world
  application). Those belong to consumers.

## Background

### Java schematic formats covered in v1.0

**Sponge Schematic Format v2** — gzipped Java NBT, used by Java WorldEdit
since ~1.13. Stores a palette of Java block-state strings keyed to integer
indices, plus a varint stream selecting the index for each cell. Cell
iteration order is `x + z*Width + y*Width*Length` (outer Y, then Z, then
X). File extension `.schem`. Spec:
[`SpongePowered/Schematic-Specification`, `versions/schematic-2.md`].

**Legacy MCEdit `.schematic`** — gzipped Java NBT, used pre-1.13 by
MCEdit, classic WorldEdit, Schematica. Stores numeric block IDs (low byte
in `Blocks`, optional high nibble in `AddBlocks`) plus damage values
(low nibble in `Data`, packed two cells per byte). Cell order matches
Sponge v2. File extension `.schematic`.

### Java↔Bedrock block-state divergence

Most Java blocks share the same identifier on Bedrock (`minecraft:stone`
== `minecraft:stone`). What diverges is property names and value encodings:

| Java property | Bedrock equivalent |
|---|---|
| `axis` (x/y/z) | `pillar_axis` (x/y/z), block-family-specific |
| `facing` (north/south/east/west) | `direction` / `weirdo_direction` / `cardinal_direction` (integer or string, varies by block) |
| `half` (top/bottom) | `upside_down_bit` (0/1) — stairs |
| `half` (lower/upper) | `upper_block_bit` (0/1) — doors |
| `hinge` (left/right) | `door_hinge_bit` (0/1) |
| `open` (true/false) | `open_bit` (0/1) |
| `waterlogged` (true/false) | (no equivalent — Bedrock represents as base block + water in same cell) |
| `lit` (true/false) | `lit` (modern protocol) or identifier swap (legacy) |

About 30 such properties span the vanilla block set. Beyond properties, a
small set of blocks have divergent identifiers (vendored as overrides).

### Translation approach

Geyser is the canonical reference for Java→Bedrock translation. Geyser
does **not** ship a flat Java→Bedrock mapping JSON; instead it builds the
mapping at runtime by walking the Java block-state space and applying
per-property converters, then validating each result against a vendored
Bedrock palette. S2D replicates this algorithm in Go.

## Decisions (locked during brainstorming)

| Decision | Choice | Notes |
|---|---|---|
| Read/write scope | Read-only (Java→Dragonfly) | No reverse translation in v1.0. |
| Format scope (v1.0) | Sponge v2 + legacy MCEdit | Sponge v3, Litematica, vanilla NBT in v1.1. |
| Block-entity handling | Skip NBT, base block only | Chest contents, sign text, etc. lost. |
| Unknown block fallback | Visible marker block | Default `magenta_wool`. Configurable via `translate.SetMissingBlock(world.Block)`. |
| Translation source | Replicate Geyser's runtime algorithm in Go | Vendored Bedrock palette + Java block schema + per-property converters. |
| API shape | Dragonfly-only (returns `world.Block`) | Library name signals it; matches Dragonfly stack. |
| Library boundary | Standalone repo | `github.com/Velvet-MC/s2d`. No `replace` directives in S2D's `go.mod`. |

## Public API

### `package schem` — top-level facade

```go
import "github.com/Velvet-MC/s2d/schem"

type Format string
const (
    FormatSpongeV2 Format = "sponge_v2"
    FormatLegacy   Format = "legacy_schematic"
)

type Block struct {
    Pos    [3]int       // x, y, z within the schematic local frame
    Block  world.Block  // translated Bedrock block (always non-nil)
    Liquid world.Liquid // non-nil iff the Java source was waterlogged
}

type Schematic struct {
    Format                Format
    Width, Height, Length int
    Offset                [3]int
    Blocks                []Block
    Unknowns              UnknownReport
}

type UnknownReport struct {
    Counts map[string]int // canonical java state string → count
    Total  int
}

// Read parses a schematic from r, auto-detecting format by filename
// extension first (".schem" → Sponge v2; ".schematic" → legacy)
// and falling back to NBT signature inspection.
func Read(filename string, r io.Reader) (*Schematic, error)

// FormatHandler describes one supported on-disk format. Format
// reader packages register their handler at init() time.
type FormatHandler struct {
    Name       Format
    Extensions []string
    Signature  func(headerPeek []byte) bool
    Read       func(io.Reader) (*Schematic, error)
}

func Register(h FormatHandler)
```

Consumer flow:

```go
f, _ := os.Open("castle.schem")
defer f.Close()
s, err := schem.Read(f.Name(), f)
if err != nil { /* ... */ }

for _, b := range s.Blocks {
    // place b.Block at b.Pos in your world / clipboard / etc.
    if b.Liquid != nil {
        // place b.Liquid in the same cell
    }
}
if s.Unknowns.Total > 0 {
    // surface s.Unknowns.Counts to the user however you like
}
```

### `package translate` — Java state → Dragonfly block

```go
import "github.com/Velvet-MC/s2d/translate"

type Result struct {
    Block      world.Block  // always non-nil; missing fallback if Recognized==false
    Liquid     world.Liquid // non-nil iff source was waterlogged
    Recognized bool
    RawKey     string       // canonical java state string (for reporting)
}

// Lookup translates a Java block-state string to a Dragonfly block.
// Safe to call from multiple goroutines; first call lazily builds the
// translation table (~100–200 ms).
func Lookup(javaState string) Result

// SetMissingBlock changes the global fallback used for unrecognized blocks.
// Default: minecraft:wool[color=magenta] (a registered Dragonfly block;
// chosen for high visibility without depending on debug blocks like
// info_update which are not in Dragonfly's registry).
//
// SetMissingBlock should be called once at consumer startup, before
// the first Lookup call. Calls after the table has been built are
// honored but are racy with concurrent Lookups.
func SetMissingBlock(b world.Block)

func MissingBlock() world.Block
```

Most consumers will never call `translate` directly — `schem.Read` already
runs each cell through `Lookup`. The `translate` package is exported so
that consumers who want to translate a single Java state string outside
the schematic-reading context can do so.

### `package palette` — Java state string parser (utility)

```go
import "github.com/Velvet-MC/s2d/palette"

type JavaState struct {
    Namespace string             // "minecraft"
    Name      string             // "oak_log"
    Props     map[string]string  // {"axis": "y"}
}

func Decode(s string) (JavaState, error)
func (j JavaState) Canonical() string  // re-emit with sorted properties
```

Pure string parsing, no Dragonfly dependency. Useful for consumers who
want to inspect or filter palette entries before translation.

### Package boundaries

- **`sponge`, `legacy`, `palette`** — pure parsing. No Dragonfly imports.
  Output is raw palette strings + cell positions + format metadata.
- **`translate`** — only place that imports `df-mc/dragonfly`. Java state
  string in, `world.Block` (and optional `world.Liquid`) out.
- **`schem`** — public facade and format dispatcher. Imports `translate`
  and the format types but not the parser packages by name; format
  readers register themselves via `init()`.

## Translation pipeline

Per-block path from raw bytes to a `schem.Block`:

```
schematic byte stream
  │ sponge.Read(r)  — gunzip, NBT decode, validate Version=2
  ▼
RawSchematic{Width, Height, Length, Offset, Palette, BlockData}
  │ for each cell index (yzx iteration):
  │   binary.ReadUvarint → palette index
  │   palette index → raw java state string
  ▼
javaStateString
  │ palette.Decode → JavaState{Namespace, Name, Props}
  ▼
JavaState
  │ translate.Lookup:
  │   1. canonicalize (strip waterlogged into liquidNeeded flag,
  │      sort props alphabetically, re-emit canonical key)
  │   2. table[canonicalKey] → world.Block (built once via sync.Once)
  │   3. if waterlogged, also set Liquid = water source
  │   4. miss → missing-block fallback + record in UnknownReport
  ▼
schem.Block{Pos, Block, Liquid}
```

### Table build (init time, sync.Once)

```
1. Parse data/java_blocks.json → []JavaBlockSchema
   Each schema: identifier + ordered list of properties + their
   value sets.

2. Parse data/bedrock_palette.1_26_20.nbt → map[bedrockKey]bedrockState
   bedrockKey = (identifier, sorted property assignment).

3. Parse data/overrides.json → map[javaIdent]bedrockIdent
   Used when the Java→Bedrock identifier is not identity.

4. For each Java block schema:
     For each combination of property values (cartesian product):
       a. Build canonical java state string.
       b. Determine bedrock identifier:
            override[javaIdent] OR javaIdent
       c. Apply per-property converters to translate Java prop set →
          Bedrock prop set.
       d. Look up (bedrockIdent, bedrockProps) in the palette to confirm
          it exists.
       e. Resolve world.BlockByName(bedrockIdent, bedrockProps) →
          world.Block.
       f. Insert table[canonicalJavaState] = world.Block.
       g. If "waterlogged" was a Java property, also insert the
          waterlogged variant with Liquid hint.

5. Resolve default missing-block once via world.BlockByName
   (default: magenta_wool; user override applied if SetMissingBlock
   was called before first Lookup).
```

The cartesian-product table holds on the order of 25k–35k entries.
Build cost: ~100–200 ms wall-clock, paid once on first `Lookup`.
Subsequent lookups: O(1) map read, no allocation.

### Property converter convention

`s2d/translate/properties/` holds one Go file per property family. Each
exports a small converter:

```go
package properties

// Axis converts Java AXIS (x|y|z) to Bedrock pillar_axis (or similar).
// The bedrockIdent argument lets the converter branch on block family
// where Bedrock uses different property names for the same Java concept
// (e.g. logs use "pillar_axis" but some other rotated blocks differ).
func Axis(javaValue, bedrockIdent string) (bedrockProp string, bedrockValue any)
```

Each converter ships with a small table-driven test in
`properties_test.go` (one shared test file walking each converter's
known-good cases).

### `overrides.json` shape

```json
{
  "minecraft:furnace": {
    "bedrock_identifier": "minecraft:furnace",
    "comment": "lit=true historically used lit_furnace identifier on legacy Bedrock; modern protocol matches Java"
  },
  "minecraft:redstone_wire": {
    "bedrock_identifier": "minecraft:redstone_wire",
    "skip_properties": ["north", "east", "south", "west"]
  }
}
```

Hand-maintained. ~50–200 entries expected for vanilla 1.0 coverage.

## Parsers

### Sponge v2 (`sponge/reader.go`)

NBT structure (Java big-endian, gzipped):

```
Required:
  Version    int32   (must == 2)
  Width      int16   (treat as uint16)
  Height     int16   (treat as uint16)
  Length     int16   (treat as uint16)
  PaletteMax int32
  Palette    map[string]int32   // "minecraft:stone[...]" → palette index
  BlockData  []byte             // varint stream

Optional:
  DataVersion    int32
  Offset         [3]int32
  Metadata       map[string]any           // ignored
  BlockEntities  []map[string]any         // ignored in v1.0
  Entities       []map[string]any         // ignored in v1.0
  Biomes                                  // ignored in v1.0
```

Cell iteration order: outer Y, then Z, then X.
Cell index formula (per spec): `index = x + z*Width + y*Width*Length`.
Total cells: `Width * Height * Length`.

Varint reader: `binary.ReadUvarint` over `bytes.NewReader(BlockData)`.
**Verify against a real `.schem` sample before locking the parser** —
Sponge spec wording is muddled but the encoding is expected to be
standard LEB128 (matches Mojang protocol varint).

Errors are wrapped with file-scope context:
`sponge v2: at cell (%d,%d,%d): %w`.

### Legacy MCEdit (`legacy/reader.go`)

NBT structure (Java big-endian, gzipped):

```
Required:
  Materials  string            // "Alpha" (Java); reject "Pocket"
  Width      int16
  Height     int16
  Length     int16
  Blocks     []byte             // numeric ID low byte per cell
  Data       []byte             // damage nibble per cell, packed 2 per byte

Optional:
  AddBlocks  []byte             // high nibble of ID for IDs > 255
  WEOriginX/Y/Z, WEOffsetX/Y/Z   int32
  TileEntities, Entities         // ignored
```

Cell iteration: same YZX order as Sponge.

Per cell:

```
i      = x + z*Width + y*Width*Length
low8   = Blocks[i]
high4  = (AddBlocks[i/2] >> (4 if i%2==0 else 0)) & 0xF   // when AddBlocks present
id     = (high4 << 8) | low8
data4  = (Data[i/2] >> (4 if i%2==1 else 0)) & 0xF
if id == 0:
    emit air; continue
javaState, ok := legacyIDs[fmt.Sprintf("%d:%d", id, data4)]
if !ok: record unknown, emit missing-block fallback
else:   translate.Lookup(javaState) → emit
```

`legacy.json` vendored from `EngineHub/WorldEdit` at the pinned commit
(MIT-licensed). ~50 KB, ~4500 entries covering MC 1.0 through 1.12.

### Format dispatcher (`schem/schem.go`)

```go
type FormatHandler struct {
    Name       Format
    Extensions []string
    Signature  func(headerPeek []byte) bool
    Read       func(io.Reader) (*Schematic, error)
}

var handlers []FormatHandler

func Register(h FormatHandler) { handlers = append(handlers, h) }

func Read(filename string, r io.Reader) (*Schematic, error) {
    ext := strings.ToLower(filepath.Ext(filename))
    for _, h := range handlers {
        if slices.Contains(h.Extensions, ext) {
            return h.Read(r)
        }
    }
    // Fallback: peek decompressed header for NBT signature.
    // ...
    return nil, fmt.Errorf("unsupported schematic format: %s", filename)
}
```

`sponge/init.go` and `legacy/init.go` register their handlers.

## Testing

### Unit (pure functions)

- `palette/palette_test.go` — `Decode`, no-namespace, no-props, malformed
  bracket, canonical re-emission stability.
- `translate/properties/properties_test.go` — table-driven, one entry per
  converter (axis x/y/z ↔ pillar_axis, facing N/S/E/W ↔ direction
  integer, etc.).
- `sponge/varint_test.go` — known byte sequences, including ≥128 and
  ≥16384.
- `legacy/ids_test.go` — known (id, data) pairs resolve to expected Java
  state strings.

### Fixture (committed binary `.schem` / `.schematic` files, all under 1 KB)

- `sponge/testdata/single_stone.schem` — 1×1×1 stone, smoke test.
- `sponge/testdata/multi_palette.schem` — 4×1×4 with ≥4 block types so
  varint multi-byte encoding is exercised.
- `sponge/testdata/waterlogged_stairs.schem` — confirms `waterlogged=true`
  → `Liquid` set on the resulting `Block`.
- `sponge/testdata/unknown_block.schem` — handcrafted with a fake
  `mod:foo` palette entry; asserts it appears in `UnknownReport` and the
  cell holds the missing-block default.
- `legacy/testdata/basic.schematic` — pre-1.13 numeric IDs only.
- `legacy/testdata/addblocks.schematic` — uses `AddBlocks` for IDs > 255.

Fixtures are checked in as binary; tests read them, call `schem.Read`,
and assert on `Schematic.Blocks` content.

### Translation table integrity (`go test ./translate`)

- `TestPaletteCoverage` — every Java state in `java_blocks.json` resolves
  to a Bedrock state in the loaded palette OR has an entry in
  `overrides.json`. Fails CI loudly on Bedrock palette upgrades that
  introduce gaps.
- `TestPaletteMatchesDragonfly` — every Bedrock identifier the table
  references resolves through `world.BlockByName`. Catches Dragonfly
  drift.
- `TestMissingBlockRegistered` — the default `magenta_wool` resolves
  through `world.BlockByName` with the exact property name Dragonfly
  uses for wool color. Test fails loudly if the property name differs
  from `color`, prompting an override.
- `TestRoundtrip` — 10 known Java states, look up, verify the resulting
  `world.Block` round-trips through `EncodeBlock()` to the expected
  Bedrock identifier+state.

### Top-level (`go test ./schem`)

- `TestReadDispatch` — feeds each fixture file, asserts the returned
  `*Schematic` has the expected `Format`, dimensions, and one
  representative cell.
- `TestReadUnknownExtension` — feeds a `.foo` file, asserts a clear
  unsupported-format error.

### Deliberately not testing
- Live Dragonfly server integration (too heavy; trust `world.BlockByName`).
- Every Java block (~25k states); table integrity covers shape, fixtures
  cover representative cases.

### Init cost

Table-build runs once, lazily, via `sync.Once` on first
`translate.Lookup` call. Estimated ~100–200 ms wall-clock the first time
a schematic is loaded; zero cost otherwise. Subsequent lookups: O(1) map
read, no allocation.

### Refresh procedure (in `translate/data/REGEN.md`)

1. When Dragonfly bumps Bedrock palette version: update
   `bedrock_palette.<new>.nbt` from Geyser at the matching commit;
   rename the constant in `table.go`.
2. Run `go test ./translate -run TestPaletteCoverage` — surfaces any new
   Java blocks lacking a Bedrock target.
3. Add new entries to `overrides.json` for divergences flagged by the
   test.
4. Tag a new S2D release.

## Open verifications (before / during implementation)

1. **Sponge v2 varint encoding is standard LEB128** (compatible with
   `binary.ReadUvarint`). Verify against a real `.schem` sample exported
   from Java WorldEdit before locking the parser.
2. **Geyser's `block_palette.1_26_20.nbt` matches the Bedrock palette
   Dragonfly's current upstream uses.** Build the table at init in a
   small repro and confirm `world.BlockByName` resolves a representative
   sample of palette entries without false negatives.
3. **`magenta_wool` resolves via `world.BlockByName("minecraft:wool",
   {"color": "magenta"})`** — verify the exact property name Dragonfly
   uses for wool color (could be `color`, `wool_color`, etc.). If it
   differs, adjust the default. Captured in `TestMissingBlockRegistered`.
4. **Source of `java_blocks.json`** — choose between Mojang's data
   generator output (canonical but requires running the data gen) vs
   PrismarineJS minecraft-data (already JSON, slight curation lag).
   Decided during S2D bootstrap; either is acceptable.
5. **`waterlogged` representation in the Java schema** — confirm whether
   Mojang's data gen / PrismarineJS lists `waterlogged` as a regular
   property or breaks it out specially. Adjust the canonicalization step
   accordingly.

## v1.1+ roadmap (informational, not in scope)

- **Sponge Schematic v3** — additive support in `sponge/`; switches on
  `Version` field. Container layout differs (blocks/biomes/entities split).
- **Litematica `.litematic`** — new `litematica/` package. Multi-region
  layout with packed long-array indices per region. Heaviest of the
  deferred formats.
- **Vanilla structure NBT (`.nbt`)** — new `vanillanbt/` package.
  Palette + position list (similar shape to Sponge v2, different field
  names).
- **Block-entity translation** — chest contents, sign text, banner
  patterns. Requires Java↔Bedrock item ID mapping and a per-tile-type
  adapter layer.
- **`.schem` writing (Bedrock → Java)** — reverse translation, requires
  a reverse table. Doubles the property-converter surface.
- **`.mcstructure`** (Bedrock-native structure block format) — useful
  identity reader (no translation needed) for Bedrock-native content.

## Acceptance criteria (v1.0)

- A consumer can call `schem.Read("castle.schem", reader)` on a Sponge
  v2 file produced by Java WorldEdit and receive a `*Schematic` with the
  expected dimensions, cells, and translated `world.Block` values
  (correctly-oriented logs, stairs, slabs, doors, fences, walls).
- Waterlogged Java blocks come back as `Block` populated with the base
  block and `Liquid` populated with water — both for the consumer to
  place.
- A consumer can call `schem.Read("oldworld.schematic", reader)` on a
  legacy MCEdit file containing vanilla MC 1.7–1.12 content and receive
  a `*Schematic` with the same shape.
- Unknown Java blocks become the configured missing-block (default
  `magenta_wool`) and are tallied in `Schematic.Unknowns` with their
  canonical Java state strings as keys.
- `translate.SetMissingBlock(b)` swaps the fallback for consumers that
